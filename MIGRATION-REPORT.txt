comma connect: React -> SvelteKit migration
===========================================

Production build, gzipped, measured on both trees at the same commit:

                        React        SvelteKit      change
    JavaScript        554,572 B      390,917 B      -29.5%
    CSS                12,081 B       18,882 B      +56.3%
    total             566,653 B      409,799 B      -27.7%

    dist/ on disk          12 M          9.2 M      -23%
    JS chunks                 8             40      finer code splitting

CSS grew because Material-UI's styling lived in node_modules and was injected at
runtime by JSS; it is now authored in the components and shipped as static CSS.
That trade is why the JS drop is larger than the net drop.


DEPENDENCIES
------------

    declared runtime deps        22  ->   9      -59%
    declared dev deps            14  ->  15      +1
    packages on a clean install 719  -> 563      -22%

Removed entirely: react, react-dom, react-redux, redux, redux-thunk,
connected-react-router, react-router, react-router-dom, history,
@material-ui/core, @material-ui/icons, @sentry/react, react-map-gl, react-player,
@vitejs/plugin-react, @testing-library/react, @testing-library/jest-dom.

Added: @sveltejs/kit, svelte, @sveltejs/adapter-static, @sveltejs/vite-plugin-svelte,
@sentry/browser.

Notable non-additions. react-map-gl was replaced with the raw mapbox-gl already
in the tree, and its WebMercatorViewport was ported into src/lib/utils/mercator.js
rather than pulling in @math.gl/web-mercator and its transitive gl-matrix and
@babel/runtime. That port is checked differentially against the real library
across 3000 randomised viewports: 0 failures, worst relative difference 2.3e-9.


TESTS
-----

                        React        SvelteKit
    suites                 11             13
    tests                  30             96     +220%
    statement coverage      -          40.61%   (.js only, as measured before)
    branch coverage         -          74.69%   (.js only)

Components are in the coverage scope now, which puts the whole-tree number at
8.02%: two of them have tests. That is the honest denominator.

Coverage is a real number now. `jest --coverage` reported 0% for every file on
both trees, because @swc/jest emits no istanbul instrumentation and the default
babel coverage provider therefore measured nothing. The v8 provider measures it.

The two sets are not the same tests. React's included component-render tests via
@testing-library; the Svelte side is unit tests over the ported logic (playback
transitions, mercator projection, route/segment maths, auth redirect handling,
thumbnail tiling, drive-list formatting, api surface). Three React suites have
direct successors; four covered redux actions, the React app shell and a window
hook that svelte/reactivity/window replaces, and were deleted with them. The two
component suites cover what a pixel diff structurally cannot see: which device a
click selects, whether a modified click is left to the browser, when the settings
button is offered, and that the account menu stays empty for a signed-out visitor
following a shared drive link.


WHAT DID NOT IMPROVE
--------------------

    production build     ~9.9 s  ->  ~12.9 s   (best of 3, same machine)

SvelteKit runs a client and a server pass even with ssr disabled. Slower than
the single React pass.

    src/ line count      17,233  ->   17,422   (+1%)

Essentially flat. The React tree lost 16,860 lines, but MUI's styling moved from
node_modules into components, so the source is a wash. The win is in the
dependency surface and the shipped bundle, not in lines of code.

    node_modules on disk   388 M  ->   378 M

Marginal, and the svelte tree currently carries puppeteer and friends installed
with --no-save for the gallery.


ARCHITECTURE
------------

  Redux is gone. Server data lives in SvelteKit load functions; the only global
  mutable state left is playback (src/lib/state/playback.svelte.js), a rune class
  over the same wall-clock arithmetic the reducer used. Route params replaced
  state.dongleId, state.primeNav and state.segmentRange.

  src/url.js is gone. Its hand-rolled path regexes became route param matchers
  (src/params/), which is stricter than what they replaced: /not-a-dongle now
  404s where the old parser accepted it and produced NaN bounds.

  Rendering is adapter-static with ssr disabled, output to dist/ with an
  index.html fallback, so Dockerfile, nginx.conf, deploy-preview.sh and the
  Cloudflare Pages setup are untouched.

NEW TOOLING
-----------

  config/mock/            A dev-server mock backend. `bun run start:mock` runs
                          every screen with no paired device and no comma
                          account, across five scenarios (default, nodevice,
                          noprime, body, anonymous). No application code knows it
                          exists and it cannot reach a production build.

TOOLING
-------

`"type": "module"` is set. Node was reparsing svelte.config.js as ESM and warning
about it on every build and every lint.

jest is gone. vitest runs the same suites plus the component ones, resolves `$lib`
from vitest.config.js and stubs `$app/*` from config/vitest/, and brings its own
jsdom, so @swc/jest, @swc/core, jest-chain-transform, jest-environment-jsdom and
the five files in config/jest/ all went with it.

oxlint does not parse .svelte, so `bun run lint` covered only the .js files —
every component was unlinted. Verified by putting an undefined reference in a
component and watching lint pass. `bun run check` now runs svelte-check over every
component and lint depends on it, so CI covers components too.


TAILWIND `important`
--------------------

src/index.css imported tailwind in `important` mode, inherited from the React
app, where every utility had to outrank Material-UI's JSS. It marked 927
declarations in the main stylesheet `!important` — that file is 63,627 bytes
uncompressed now against 71,439 before — and it inverted two cascade rules the
components were quietly depending on:

  - an inline style no longer beat a utility, so `style="font-size:24px"` on an
    icon lost to a `text-*` class on the same element
  - a scoped class no longer beat a utility, so a component's own `.body1` lost
    to `text-white/80`

Both are load-bearing in places, so the flag could not simply be dropped. Every
site was found statically — utilities stacked on the same property, scoped
classes against utilities with shorthands expanded, and inline styles against
utilities — and each was pinned to the value the `important` build computed
before being rewritten to declare it outright. Eleven sites across six files.
`.glass` and `.glass-dark` exist for that reason: they are the glass treatment
without a tint, so a caller that brings its own background composes with them
instead of stacking a second `bg-*` on `.bg-glass` and letting emission order
decide.

One of those sites was dead rather than ambiguous. The comma body's bumper tints
blue while its camera is active, set with an inline style that the `important`
utility on the same element had been silently beating, in React as well. It
renders now. That is the one place this branch deliberately differs from the
React app.


ROUTING PARITY
--------------

url.js parsed the path with two loose regexes, and their overlap carried more
meaning than it looked like it did.

getSegmentRange matched `/{dongleId}/{logId}/{start}/{end}`, the URL the timeline
writes when a range is selected, with the range in whole seconds of route-relative
offset. That is now a real route rather than a stub, so zooming the timeline no
longer navigates away from the drive. Ranges are clamped to the route, which the
reducer did not do; a hand-typed range used to leave the timeline unusable.

getZoom also matched `/{dongleId}/{start}/{end}`, which nothing ever generated:
urlForState only emitted a range after a log id, and without one there was no
current route, so explorer rendered the dashboard and the zoom went unused. That
path now redirects to the dashboard instead of carrying a dead range.

App.jsx computed `showLogin` from those same two functions, which is what made a
shared drive link open the explorer for a signed-out visitor. A log id in the path
is what a shareable URL has, so that is the test the layout uses. Every other
signed-out path renders the landing page, as anonymousRoutes did, and the path is
kept in sessionStorage so signing in returns to it.


KNOWN GAPS
----------

  - Two components have tests. The runner is no longer the reason; the other
    forty-odd are simply not written yet.
  - The body line-height is not a shim, despite what this file used to call it.
    Material-UI's CssBaseline sets no line-height at all: 1.46429 is the body1
    variant, which MUI applied per Typography component and which most ported
    text needs. Eighteen elements that were raw markup in React carry an explicit
    1.5. Making it per-element instead would mean annotating the majority to
    avoid annotating the minority.
  - Clips download returns an error in mock mode by design; real video needs a
    real route.
  - The map is comma's own mapbox style, which is dark, and stays dark under the
    light theme. Swapping in a stock light style would change the product's
    cartography, so it is left for comma to decide.
